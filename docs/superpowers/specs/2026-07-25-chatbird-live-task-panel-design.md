# ChatBird 实时任务面板设计规格

日期：2026-07-25

## 目标

在现有 ChatBird macOS 悬浮面板中改进周额度和 Codex 任务列表，使用户能快速判断额度风险、识别任务状态，并在不切换到 Codex 的情况下了解运行中任务当前公开的工作进展。

本次只调整现有面板的数据、交互和视觉反馈，不改变宠物主体、面板锚点或点击任务跳转到 Codex 的既有行为。

## 已确认的用户体验

### 周额度

- 只显示当前可用的周额度，不恢复已经从 Codex 产品中移除的 5 小时额度。
- 剩余 `50%–100%` 使用现有蓝色。
- 剩余 `20%–49%` 使用黄色。
- 剩余 `1%–19%` 使用红色。
- 剩余 `0%` 使用灰色空环，百分比数字保持红色，并显示“额度已耗尽”。
- 自动刷新频率从每 5 分钟改为每 1 分钟。
- 更新时间右侧显示可点击的刷新图标。手动刷新与自动刷新复用同一刷新流程，刷新进行中时图标旋转。
- 不显示“每 2 秒更新”“2 秒前更新”一类持续变化的说明文字。

### 任务排序与状态

- 所有任务按最后更新时间 `updatedAt` 倒序排列，不按创建时间排列。
- 运行中使用蓝色旋转图标。
- 等待用户输入或确认使用黄色问号/时钟图标。
- 已完成使用绿色勾选图标。
- 失败使用红色警告图标。
- “等待输入”属于活跃任务，和运行中任务共同参与活跃任务数量和排序。
- 每一行继续支持点击，并通过 `codex://threads/{threadID}` 打开对应 Codex 任务。

### 最多五行与滚动

- 活跃任务数量大于 5 时，列表只包含运行中和等待输入的任务。
- 此时可视区域固定为 5 行高度，支持鼠标滚轮和可见的纵向滚动条。
- 活跃任务数量不大于 5 时，先显示全部活跃任务，再用最近更新的已完成或失败任务补位，最多显示 5 行。
- 任务变化、排序变化或数据刷新后，滚动位置会被限制到新的有效范围，避免出现空白列表。

### 运行中任务悬停预览

- 只对运行中任务显示悬停预览；等待输入、完成和失败任务不显示动态工作内容。
- 悬停预览使用非激活、不可抢焦点的轻量 `NSPanel`，位于任务行附近，避免遮挡主列表。
- 预览标题固定为“Codex 正在处理”，正文是固定尺寸的三行尾部字符窗口；文本按字符自然换行，超过三行后保留能够完整放入容器的最长文本尾部，新字符到达时从开头逐字覆盖旧内容，窗口不随历史内容增高。
- 正文不使用尾部省略号；类似 `abcdefg → bcdefgh → cdefghi` 的滑动替换始终展示最新字符。
- 用户保持悬停时，新活动段到达后直接更新预览，不要求移出再移入。
- 鼠标离开任务行、任务不再运行、主面板隐藏或应用退出时，预览立即关闭。
- 靠近屏幕边缘时，预览自动改变方向或限制在当前屏幕的可见区域内。

## 活动摘要的数据边界

ChatBird 不连接、不接管 ChatGPT/Codex 当前使用的标准输入输出 app-server。活动摘要来自现有 rollout 文件扫描，因此采用“分段准实时”，而不是逐 token 流式传输：

- 新的公开 commentary 段写入 rollout 后，悬停预览在下一次任务进度扫描时更新。
- 结构化工具调用开始或结束时，活动摘要随扫描结果更新。
- 不解析、不展示 `agent_reasoning`、隐藏思考、工具参数、命令正文、工具原始输出、凭据或其他敏感内容。

安全化摘要的优先级：

1. 当前仍在运行的结构化工具活动。
2. 当前任务最新的公开 commentary，以三行可见字符尾部窗口滚动覆盖。
3. 无公开活动时显示“正在思考”。

结构化工具活动只映射为有限的通用描述：

- `exec_command`：正在运行命令
- `apply_patch` 或文件编辑工具：正在编辑文件
- web、browser 或搜索工具：正在搜索或检查网页
- 其他工具：正在使用工具

公开 commentary 会移除 Markdown 装饰，并把换行及连续空白折叠为单个空格。连续公开片段按写入顺序追加为同一段话；数据层只保留有界的最近字符，渲染层再使用实际字体和可用宽度测量文本，保留能够完整放入三行的最长字符尾部。工具状态与公开输出共同参与同一个段落和尾部窗口。工具参数和输出不参与摘要生成。

## 数据模型与解析

`TaskProgressItem` 增加：

- `updatedAt: Date`：用于全局排序和补位选择。
- `activityText: String?`：仅保存可公开展示的安全化活动摘要。

`updatedAt` 的选择顺序：

1. rollout 中最后一个与任务状态或公开活动有关的事件时间。
2. rollout 文件修改时间。
3. 缺失时回退到任务开始时间。

解析器以 `call_id` 跟踪尚未结束的工具调用。收到对应 output 后移除活动工具。等待输入仍由 `request_user_input` 识别；收到后续用户消息后恢复为运行状态。

任务快照先完成线程去重，再按 `updatedAt` 倒序排序，最后应用活跃优先和五行展示规则。

## 组件边界

### `CodexTaskProgressReader`

负责读取 rollout、识别任务状态、计算 `updatedAt`、生成安全化活动摘要。它不负责布局、滚动或悬停窗口。

### `TaskProgressSnapshot`

负责线程去重、更新时间排序、活跃/终态分组和最终列表选择。它提供完整的可滚动活跃列表或最多五条的混合列表。

### 主面板绘制与交互

负责额度颜色、刷新图标、任务状态图标、五行裁剪、滚动条、滚轮命中和任务点击跳转。

### 悬停预览控制器

负责预览窗口生命周期、屏幕边界定位，以及在同一悬停任务的新快照到达时更新正文。它只接受已经安全化的 `activityText`。

## 刷新与性能

- 额度网络刷新保持独立计时器，周期为 60 秒。
- rollout 文件的轻量扫描周期可以短于额度刷新周期，以支持分段准实时悬停更新。
- UI 不显示扫描频率，也不显示相对秒数。
- 继续限制候选 rollout 数量和新鲜度窗口，避免遍历完整历史。
- 只有数据或活动摘要发生变化时才触发必要的界面重绘和悬停预览更新。

## 错误处理

- 额度刷新失败时保留最后一次成功数据，并结束刷新图标动画；已有额度时继续显示旧值，只在底部提示一分钟后重试。
- 首次读取即失败时显示简短中文状态，不把 Codex app-server 的英文错误、响应正文或其他底层诊断信息绘制到面板。
- rollout 文件暂时不可读、格式不完整或正在写入时跳过损坏事件，保留上一份有效快照。
- 活动内容无法安全解析时回退到“正在思考”，不显示原始内容。
- 打开任务 URL 失败时不使用辅助功能、鼠标或键盘事件作为兜底。

## 验证标准

### 自动测试

- 额度阈值在 `50%`、`20%`、`1%`、`0%` 边界使用正确颜色和 0% 文案。
- 自动额度刷新间隔为 60 秒，手动刷新复用刷新流程。
- 任务按 `updatedAt` 而不是 `startedAt` 排序。
- 等待输入被计入活跃任务。
- 活跃任务大于 5 时只返回活跃任务，并产生有效滚动范围。
- 活跃任务不大于 5 时用最近更新的完成/失败任务补到最多 5 条。
- 四种主要状态映射到不同图标和颜色。
- 工具开始、工具结束、公开 commentary 和无公开活动四种情况生成正确摘要。
- `agent_reasoning`、工具参数和工具输出不会进入 `activityText`。

### 手动与视觉验证

- 面板保持用户确认的横向尺寸和位于宠物正上方的位置。
- 五行任务在普通、滚动和悬停状态下无裁切、重叠或跳动。
- 刷新图标可点击，旋转期间不阻塞其他交互。
- 悬停预览不抢焦点，内容在保持悬停时能随新公开活动段更新。
- 点击每条任务仍能打开正确的 Codex 任务。
- 主面板隐藏后悬停预览不会残留。

### 隐私与输入安全审计

- 源码中不存在 `CGEvent`、键盘注入、鼠标注入或模拟点击。
- 不附加到 ChatGPT/Codex 的现有 stdio app-server。
- 不显示内部推理、原始命令、工具参数或工具输出。

## 交付范围

交付包括源码调整、扩展后的自测、Universal macOS 构建、视觉验证、隐私审计、安装包与 SHA-256。安装在所有验证完成后只进行一次，以减少 ad-hoc 签名变化对 macOS 辅助功能授权的影响。
